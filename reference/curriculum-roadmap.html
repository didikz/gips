Structured curriculum

Image Processing Service · stdlib-first · production-grade

Each lesson ships one slice of the roadmap.sh project. Deploy: Docker → GHCR → kind → Helm → VPS/k3s when ready. Data: SQLite + Redis + R2.

# Lesson Delivers Deps
1 Project skeleton & HTTP GET /healthz, package layout, go run stdlib
2 Config & graceful shutdown slog, env config, signal handling, context stdlib
3 Docker containerization Multi-stage Dockerfile, docker compose (app + Redis) Docker
4 GitHub Actions CI/CD go test on PR; build + push image to GHCR on main GitHub Actions
5 Middleware & routing Request ID, logging middleware, ServeMux patterns stdlib
6 SQLite persistence database/sql, migrations, internal/store/ functions + modernc.org/sqlite
7 Registration & login POST /register, POST /login, password hashing + x/crypto/bcrypt
8 JWT auth middleware Protect image routes + JWT library
9 Image upload POST /images, multipart, metadata → SQLite, bytes → disk stdlib
10 Transform pipeline Resize, crop, rotate, format conversion stdlib (+ maybe x/image)
11 Retrieve & list GET /images/:id, paginated list stdlib
12 Redis transform cache Cache-aside for transformed images, TTL, invalidation + redis/go-redis/v9
13 Production hardening Rate limits (Redis), load test, error taxonomy mixed
14 Async transforms (Redis Streams) XADD jobs; worker XREADGROUP Redis
15 Cloudflare R2 storage Swap local disk for R2; S3-compatible API + AWS SDK v2
16 Kubernetes deployment kind cluster, Deployment/Service/ConfigMap/Secret/PVC, probes kind + kubectl
17 Helm chart Templatize manifests; values.yaml + helm install/upgrade/rollback Helm 3
18 VPS deploy (k3s) Single-node k3s on your VPS; same chart, values-vps.yaml VPS when ready

Principles

  • Effective Go governs naming, errors, and package design.
  • Every lesson ends with a running, testable, containerizable increment.
  • CI stays green from lesson 4 onward — tests added alongside features.
  • Deploy path: Docker → GHCR → K8s manifests → Helm chart → VPS (optional).
