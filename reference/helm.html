Helm chart

Lesson 17 · after plain K8s manifests (lesson 16)

Why after lesson 16?

Helm templates the YAML you already understand. Lesson 16 teaches Deployment, Service, etc. Lesson 17 wraps them in a chart so dev (kind) and prod (VPS) differ only by values file.

Chart layout

deploy/helm/gips/
├── Chart.yaml
├── values.yaml              # defaults (kind / local)
├── values-vps.yaml          # your VPS overrides (lesson 18)
└── templates/
    ├── deployment.yaml
    ├── service.yaml
    ├── configmap.yaml
    ├── secret.yaml
    ├── redis-deployment.yaml
    ├── redis-service.yaml
    ├── pvc.yaml
    └── _helpers.tpl

Lesson 17 delivers

  • Convert deploy/k8s/ manifests → Helm templates
  • values.yaml — image repo/tag, replicaCount, resource limits, env
  • helm install gips ./deploy/helm/gips on kind
  • helm upgrade after CI pushes new image tag
  • helm rollback when a deploy breaks

Values example

# values.yaml (kind / local)
image:
  repository: ghcr.io/didikz/gips
  tag: latest
replicaCount: 1

redis:
  enabled: true

persistence:
  enabled: true
  size: 1Gi

ingress:
  enabled: false
# values-vps.yaml (when VPS is ready)
ingress:
  enabled: true
  host: gips.example.com

image:
  tag: "sha-abc123"   # pin from CI, not :latest

Commands

helm lint ./deploy/helm/gips
helm install gips ./deploy/helm/gips -n gips --create-namespace
helm upgrade gips ./deploy/helm/gips -f values-vps.yaml
helm history gips -n gips
helm rollback gips 1 -n gips
