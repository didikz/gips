Kubernetes deployment

Lesson 16 · after the service is feature-complete

Why lesson 16?

K8s needs something worth deploying. By lesson 16 you have: container in GHCR, Redis cache/queue, R2 storage, async workers. Manifests map to real env vars and volumes — not a toy hello-world.

Yes, K8s is heavy for a solo image API — but your goal is to learn it on a project you understand end-to-end.

Local cluster: kind

Use kind (Kubernetes in Docker) — you already have Docker from lesson 3.

kind create cluster --name gips
kubectl cluster-info --context kind-gips

Manifest layout

deploy/k8s/
├── namespace.yaml
├── configmap.yaml       # PORT, REDIS_ADDR, IMAGE_STORAGE_PATH, …
├── secret.yaml          # JWT_SECRET, R2 keys (gitignored template + example)
├── redis-deployment.yaml
├── redis-service.yaml
├── gips-pvc.yaml        # SQLite + local cache path (single replica)
├── gips-deployment.yaml # replicas: 1 while using SQLite
├── gips-service.yaml
└── ingress.yaml         # stretch: path routing to gips

SQLite on K8s — be honest

Constraint: SQLite = one writable replica. Run replicas: 1 for gips until you swap to Postgres. This is a learning deployment, not multi-region HA. The lesson teaches K8s mechanics; the data layer limitation is called out explicitly.

Deploy flow

# image already in GHCR from lesson 4 CI
kubectl apply -f deploy/k8s/namespace.yaml
kubectl apply -f deploy/k8s/

kubectl port-forward svc/gips 8080:8080 -n gips
curl localhost:8080/healthz
