Project layout

Stdlib service · github.com/didikz/gips

gips/
├── cmd/gips/main.go          # minimal main: parse flags, start server
├── internal/                 # private application code (not importable)
│   ├── config/config.go      # env-based configuration
│   ├── db/db.go              # Open SQLite, run migrations
│   ├── store/                # flat SQL functions (user.go, image.go)
│   ├── cache/                # Redis helpers (lesson 10+)
│   ├── httpserver/server.go  # routes, passes *sql.DB to handlers
│   └── http/handler/         # HTTP handlers call store directly
├── data/                     # gitignored: gips.db, uploaded images
│   ├── gips.db               # SQLite (created lesson 4)
│   └── images/               # original + derived blobs
├── go.mod
├── deploy/
│   ├── k8s/                  # plain manifests (lesson 16)
│   └── helm/gips/            # Helm chart (lesson 17)
└── lessons/ …                # teaching materials (not shipped)

Rules

  • cmd/ — one directory per binary; keep main thin.
  • internal/ — enforced privacy; only this module can import it (Go 1.4+).
  • Package name = directory name — short, lowercase, no underscores (Effective Go).
  • No utils package — name by responsibility (handler, store, config).
  • Stay flat — handlers → store functions → SQL. No ORM, no repository interfaces unless a second impl appears.
  • Deploy path — Docker → GHCR → deploy/k8s/ (lesson 16).
